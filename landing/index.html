01 / THE PROBLEM

Provider sprawl is a reliability problem.

Multiple provider SDKs mean fragmented keys, silent 429 cascades, and unexpected invoices. Tanvelo consolidates everything into one controlled path.

WITHOUT TANVELO
  • Silent 429 Failures: Upstream rate limits crash client requests without a backup path.
  • Three Divergent SDKs: Inconsistent error models, authentication keys, and wrapper glue code.
  • Uncapped Spend: Budget runaway discovered weeks later on provider billing dashboards.
WITH TANVELO
  • 184ms Automated Failover: Rate limits and 5xx errors automatically fail over to Claude or Gemini.
  • One Unified Endpoint: Standard OpenAI SDK drop-in. Change only base_url and key.
  • Atomic Limits & Budgets: Enforce strict spend caps with standard X-RateLimit headers.
02 / CAPABILITIES

Production controls, not an opaque proxy.

Three fundamental capabilities engineered for teams shipping LLMs to real users.

01

Deterministic Routing

Declare primary models, retries, and ordered fallbacks per project. Tanvelo executes deterministic rules — never an unpredictable AI black box.

02

Atomic Redis Limits

Token-bucket rate limits per key and project. Hard monthly budget cutoffs prevent recursive agent loops from draining capital.

03

Request Audit Ledger

Every request records an auditable trail: latency waterfall, upstream attempt status, token metrics, and estimated costs.

03 / QUICKSTART

From zero to first request in 60 seconds.

Keep your existing OpenAI SDK. Point the base URL at Tanvelo. 

from openai import OpenAI

client = OpenAI(
    base_url="https://api.tanvelo.com/v1",
    api_key="tv_live_948f2b...",
)

response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Ship to production."}],
    stream=True,
)

for chunk in response:
    print(chunk.choices[0].delta.content or "", end="")
import OpenAI from "openai";

const client = new OpenAI({
  baseURL: "https://api.tanvelo.com/v1",
  apiKey: process.env.TANVELO_API_KEY,
});

const stream = await client.chat.completions.create({
  model: "gpt-4o",
  messages: [{ role: "user", content: "Ship to production." }],
  stream: true,
});

for await (const chunk of stream) {
  process.stdout.write(chunk.choices[0]?.delta?.content || "");
}
curl https://api.tanvelo.com/v1/chat/completions \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer $TANVELO_API_KEY" \
  -d '{
    "model": "gpt-4o",
    "messages": [{"role": "user", "content": "Ship to production."}],
    "stream": true
  }'
04 / SECURITY

Guardrails you can inspect.

Security is not a badge at the bottom of the page. It is a verifiable set of architectural controls.

Gateway Keys

Cryptographically random, displayed once, stored exclusively as SHA-256 hashes.

Provider Secrets

Master keys are encrypted at rest with AES-256-GCM. Never exposed to browsers.

Webhooks & SSRF

HMAC-SHA256 signatures with bounded retries and RFC1918 egress protections.

Zero Prompt Retention

Bodies sanitized by default; full body storage is strictly opt-in and off by default.

Honesty by default: No invented uptime metrics, fake logos, or synthetic charts.
